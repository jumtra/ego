# セキュリティモデル

[ドキュメント索引](README.md) · [English](../en/security.md)

**ego は OS のサンドボックスではありません。** ステージング用コピーや Git worktree は、レビューされていない変更から作業ツリーを守ります。しかし、AI CLI が起動したプロセスが、ホームディレクトリ、環境変数、その他のパスを読むこと、またはネットワークを使うことは止めません。このため、`ego doctor` はサンドボックスを未検証として報告します。

## ego が守るもの

| 領域 | 保護の内容 |
|---|---|
| セットアップ時のファイル | `ego init` と `ego sync` は `--apply` がない限りプレビューのみです。生成ファイルはハッシュで追跡されます。編集済みのファイルは決して上書きされません（`BLOCKED`）。`CLAUDE.md` / `AGENTS.md` は管理ブロック内のみ変更されます。適用のたびに `ego rollback` 用のスナップショットを作成します |
| 管理実行中の作業ツリー | 作業はステージング用コピーまたは worktree で行います。適用には `--apply --approve` が必要です。変更された全ファイルが `write_allowlist` に一致する必要があり、対象は run の開始後に変更されていてはなりません（`STALE_BASE`） |
| チェックコマンド | シェルを介さず argv 配列として実行し、`allow_commands` に限定します。シェル、`python -c`、破壊的なパターンは拒否されます。`strict` ポリシーでは、`git push`、`reset`、`clean`、`rebase` も拒否されます |
| 実在の AI CLI の起動 | `--trust-cli` が必要です。権限確認のスキップには、`--autonomy bypass` と `--attest-external-sandbox` の両方が必要です |
| プロンプト | 前のノードの出力を後のプロンプトにそのまま追加することはありません。後のノードは検証済みのファイルを読みます。参照ファイルとチェックポイントは、信頼できないデータとしてラベル付けされます |
| skill とプロンプトの変更 | ハーネスが管理する skill の説明、マーカーで区切られた skill 本体、ツールガイドに限定されます。昇格には評価の証拠と `--approve` が必要で、元に戻せます |
| 支出 | `ego optimize` は既定でオフです。従量課金でない実験には `--spend-approval` が必要です。プランナーのモデル呼び出しには `--execute` が必要です |
| 更新 | `ego update` は GitHub リポジトリ、HTTPS、wheel 名、安定版のバージョン、GitHub API から得た SHA256 を固定します。任意の URL、シェルパイプライン、依存関係のインストールは行いません。git チェックアウトは fast-forward のみです |
| 保存されるデータ | チェックポイントとメモリはプロジェクト内に残ります。会話のトランスクリプトは収集しません。秘匿化フィルターが、永続化された run の結果から一般的な認証情報の形式を取り除きます |

## 守らないもの

- **AI CLI が起動したプロセス。** 許可されたコマンド名とポリシーのフックは助言的なもので、セキュリティの境界ではありません。
- **`--yolo` と `bypass`。** `ego run --yolo`、`run_yolo = true`、`--autonomy bypass` は、CLI 自身の権限確認を取り除きます。受け入れられる場合にのみ使ってください。
- **AGY の書き込みを伴う run。** AGY の print モードは権限確認に応答できないため、管理された書き込み run は `--attest-external-sandbox` がなくても `--dangerously-skip-permissions` を渡します。読み取り専用のノードと `--autonomy safe` は plan モードを使います。編集はステージング用コピーに入りますが、AGY が実行するコマンドは封じ込められません。AGY の計画で自動化された CLI 利用が許可されているかどうかは、あなたが確認してください。
- **コスト。** 報告されるコストは、事後の CLI 自身の見積もりであり、ハードな上限ではありません。`--max-budget-usd` は、報告されたコストがそれを超えると、ステップの区切りで run またはループを停止します。
- **コンテンツ内の機密情報。** 秘匿化はベストエフォートです。ソースファイル、図、特殊な形式の中の認証情報は検出されないことがあります。
- **本人確認。** `--approval-ref` はローカルの監査用メモであり、誰が承認したかの証明ではありません。
- **サーバー側のルール。** ブランチ保護と必須チェックは GitHub 上で設定する必要があります。
- **`relaxed` ポリシー。** AI に、依頼に応じて push と設定編集をしてよいと伝え、ほとんどのフックのチェックを無効にします。

## 外部ツール

- AI CLI、CodeGraph、Graphify、Engram を ego が導入することはありません。`ego code index --execute` は、プロバイダの文書化されたインデックス作成コマンドを実行します。ローカルのインデックスを書き込むことがあります。
- Engram は `EGO_ENGRAM_MCP_COMMAND` から起動されます。これは、あなたが設定し信頼するコマンドです。実際のサーバーが応答するまで、互換性は前提としません。
- CLI のフラグのサポートは、ベンダーの `--version` と `--help` だけを実行して検出し、実行ファイルごとにキャッシュします。必要なフラグがない場合は、安全側に倒して失敗します。

## 推奨事項

重要なリポジトリでは、本番の認証情報がなく、ネットワークポリシーが固定され、最小権限のトークンを持つ、外部のサンドボックスや使い捨ての VM で管理された作業を実行してください。`policy_mode = "strict"` を維持してください。`.ego/state/`、`.ego/backups/`、`.ego/locks/`、`.ego/memory/handoffs/`、ログ、認証情報はコミットしないでください。

## 検証済みの内容

テストスイートは `mock` ホストでオフラインに実行されます。対象は、設定、インストールとロールバック、タスクのルーティング、run とループのエンジン、チェックポイント、フック、`ego run` のラッパーのロジック、アップデーターの検証です。実在のベンダー CLI の振る舞いは、テストで端から端まで実行されるのではなく、各 CLI が報告するフラグと照合されるアダプターを通じて扱われます。Engram、CodeGraph、Graphify、`gh` との連携は、外部ツールに依存するアダプターです。マシン上で `ego doctor` と小さな試運転を行って確認してください。
